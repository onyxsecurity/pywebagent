Why this ticket exists

PRDCT-11935's C2 lifecycle leg (pr-verifier rule C2 clause 5: "a second scan after the artifact is removed shows it stale or marked deleted — not resurrected and not duplicated") was driven for real on the head build: the skill directory, subagent definition, and MCP bundle were removed from the scanned machine and a second real scan ran through the full ingest path. Measured result: the product has NO representation of "stale or marked deleted" for these classes — the demand's first half is unrepresentable today, on BOTH ingestion lanes. The not-resurrected / not-duplicated half was proven (exactly one asset row per artifact identity across both scans). PRDCT-11935 ships the transport; this ticket carries the product gap.

What was measured (PRDCT-11935 PR evidence, head build)

Removed skill / subagent / MCP-server assets stay AssetStatusDiscovered, is_deleted = f, updated_at frozen, forever (evidence at7-41: removal + second scan on the head image; scan completed, subjects absent from payload, rows unchanged).
The removed MCP bundle's tools stay is_active = t (same evidence).
The SPA renders the removed MCP server live ("Tools 5"), with no Deleted/Stale badge; skills and subagents likewise render as ordinary discovered assets (independent verifier drive, PRDCT-11935 verify round 23).
Desktop agents were initially described here as the one class with a product-visible staleness signal; measurement REFUTED that (correction posted as a comment on this ticket, 2026-08-21; PRDCT-11935 evidence at7-44). The SPA's "Last Seen" is bound to updated_at, not last_scanned_at (frontend/app/src/routes/ai-assets/desktop-agents/group/-components/instances-table.tsx:334-335; group-overview.tsx:115 passes lastSeen={group.updated_at}, rendered day-granular at :216-221), and it renders the identical value for an uninstalled agent and every still-installed control. desktop_agent_applications.last_scanned_at — the class's real per-artifact freshness column, advanced by the upsert on every scan that observes the runtime — is rendered by NO UI surface (grep last_scanned_at frontend/ = 0 hits; its only exposure is the device-level raw timestamp on the external API, crud_service/api/v2_models/devices.py:88, which is not a rendering of a stale/deleted state). Agents are also never marked deleted: the DeletedBadge at desktop-agents/$appId.tsx:307 is gated on is_deleted, which no scanner-lane writer sets, and the group instances table filters is_deleted rows out entirely (instances-table.tsx:424,502). The desktop-agent class is therefore IN SCOPE for this product gap — alongside skills / subagents / MCP servers, which have no rendered timestamp or badge at all. (Scope extended by PRDCT-11935's round-28 plan amendment, 2026-08-21; the class's last_scanned_at staircase remains the natural per-artifact last-observed PRECEDENT any fix can build on — tracked today, rendered nowhere.)

Root causes (file:line)

The AssetStatus enum has exactly three values — Sanctioned / Unsanctioned / Discovered — no stale or removed state exists in the type system: backend/internal/db/ent/schema/asset.go:61, backend/internal/db/ent/schema/assetstatus_enumer.go:12,38; mirrored in backend_python/src/common_db/models/assets.py:42-44 and the generated crud client.
The assets table carries only status + is_deleted as lifecycle-capable columns, and no ingestion writer moves either on absence: the new writer's only keep-set soft-delete is for agent→MCP-server EDGES (backend_python/src/endpoint_asset_ingestion/ingestion/mcp_writer.py:1611,1651, calling soft_delete_old_agent_mcp_connections — reconciles only agents a payload CONTAINS); the only asset-row soft-delete touchpoint in the ingestion package is backend_python/src/endpoint_asset_ingestion/ingestion/swg_writers.py:570 _restore_soft_deleted, which UN-deletes.
Gen-1 (Go/Temporal ScannerTenantWorkflow) behaves identically: the only SetIsDeleted(true) on an asset in the Go backend is the Dataverse integration's DisableApp (backend/internal/repository/agent/agent.go:326) — nothing scanner-lane. Cross-lane product fact, not a lane divergence.
The frontend accordingly ships no stale/deleted badge for these classes (no status value exists for it to render).

Design constraint any fix must honor

"Absence is not a delete instruction" is deliberate and prior-ticketed: the writer's own reconcile docstring (backend_python/src/endpoint_asset_ingestion/ingestion/mcp_writer.py, reconcile_agent_mcp_connections) names the accepted trade — an agent that genuinely removed its artifacts "keeps its stale connections until a positive-evidence staleness reaper prunes them", mirroring the old lane's DESKTOP_AGENT_MCP_SKIP_EMPTY_DISPATCH_PATCH and the original PRDCT-6301 fix ("treat an empty incoming set as no signal, not remove-everything"). A machine that is merely offline (or a payload split across S3 objects) must not have its assets reaped or marked deleted by a scan that simply didn't see them. A real fix needs deliberate staleness semantics — e.g. per-artifact last-observed timestamps + a UI stale threshold, or an explicit removal signal emitted by the scanner when it positively observes the artifact gone — designed once and applied to the SHARED writer path so both lanes (until gen-1 retires) and every cloud stay convergent.
