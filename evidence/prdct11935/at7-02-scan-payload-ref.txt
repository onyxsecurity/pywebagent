=================== 3. THE STORED IDENTITY IS DERIVED, NOT COPIED — the strongest form of the fidelity claim ===================
    This is worth stating precisely, because it is what makes d-c2-fid-skills / -subagents mean
    something. The payload carries its OWN `contentHash` field, and the product does NOT store it:
        on-disk SKILL.md                       562 bytes  sha256 4fa01a12e3d0b98ed9043a7f904109a3d4f02fd4656ebb12751bdb698f1d7714
        payload skillMdContent                 562 bytes  sha256 4fa01a12e3d0b98ed9043a7f904109a3d4f02fd4656ebb12751bdb698f1d7714
        payload's own contentHash field                       d1c7fe7a87cb7fe8da34b1a82860d19759ed6d1f3f4fd56bbc35e0a7e9312991
        byte-identical to the file on disk?    True
    Read those three values together. The payload's contentHash field is d1c7fe7a…; the value the
    product stored as agent_skills.skill_md_hash is 4fa01a12…, which is the sha256 of the skill's actual
    content and equals the digest sha256sum computed on disk. So the lane derived the identity from the
    content itself rather than trusting a field the payload handed it — the equality between disk and DB
    cannot be an artefact of copying, because the one number in the payload that could have been copied
    is a different number.
