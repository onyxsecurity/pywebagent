# WHY THIS LEG EXISTS. This PR deletes a dead Azure branch from scanner_event_consumer_service and
# mcp_gateway_event_consumer_service and adds an assert_cloud_supported validator to both. Those two
# hunks EXECUTE at boot on every AWS cell, so reading the diff is not enough: the services have to
# boot and consume for real on both images and behave the same. Each service keeps its own unchanged
# ConfigMap across both legs; only the image moves.
#
# The validator passing is not a log line to look for — it is a model_validator, so a pod that
# reaches 'SQS client connected' has already passed it. Booting IS the assertion.
#
# ONE METHOD FIX, WORTH STATING. The first two attempts at this leg came out asymmetric (2/2 on one
# image, 0 on the other) and the cause was the harness, not the code: a TERMINATING pod still polls
# its queue, so a message driven right after a rollout can be eaten by the image not under
# measurement. The leg now blocks until exactly one pod per consumer is alive, purges both queues,
# and only then drives. Recorded because a reader deserves to know the first numbers were wrong and
# why, rather than seeing only the run that agreed.
