## 1. THE INDUCTION — a real deterministic DB fault scoped to ONE agent, no mock and no code change
   The class is reached when per-agent isolation abandons a slice: a NON-transient failure inside one
   agent's identity write is swallowed so its siblings still land (writers.py:804-812), the agent is
   added to `abandoned`, and the object then meters processed_with_failures instead of processed.
   To reach it without touching code, a real CHECK constraint was placed on the tenant's assets table
   naming exactly one detected runtime:

       alter table onyx_security.assets
         add constraint r29_slice_probe check (name <> 'Codex (coder)') not valid;

   `not valid` skips existing rows, so only NEW writes are checked — i.e. only this scan's Codex slice.
   A check violation is SQLSTATE 23514, which is deliberately NOT in the transient set
   (common/database/pg_retry.py: _RETRYABLE_SQLSTATES has no 23514 and class 23 is not a retryable
   class), so retry_reason_for() returns None and the isolation path — not the retry path — is taken.
   That is the whole point of the induction: it exercises the real branch rather than simulating it.
