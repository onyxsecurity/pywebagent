Design constraint any fix must honor

"Absence is not a close instruction" is deliberate (the LLM-hiccup rationale above; lineage: PRDCT-6301 "empty incoming set = no signal"). A machine that is merely offline, or a payload split across objects, must not auto-resolve real findings. The natural fix rides POSITIVE-EVIDENCE staleness — PRDCT-12069's per-artifact last-observed / explicit-removal-signal design: once an absent artifact's asset row is marked deleted, the ALREADY-EXISTING unlink_deleted_assets_from_issues hook closes its instances with no new close semantics needed. Decisions this ticket owns beyond that: (a) whether the evidence-refresh loop (re-writing Evidence from cached findings on every re-affirm) should be tempered; (b) whether /posture-issues should surface finding freshness (classified_at is rendered nowhere); (c) whether a re-affirmed issue whose source was last observed N scans ago deserves a distinct state or annotation.
