  4.2 Helm. Two kinds of change, both inert on AWS:

        queue/consumer_pool.py           the only caller. It backs off ONLY when the client returns True:
                                  released_immediately = await client.abandon_message(msg)
                              except Exception:
                                  logger.exception("Failed to release message for redelivery", worker_id=worker_id, message_id=msg.id)
                                  released_immediately = False
          
                              # Pace the retry, but ONLY where the broker re-offers the message at once. Service Bus
                              # does, and each attempt counts against the queue's max_delivery_count, so without this
                              # a dependency outage cycles receive -> fail -> abandon at full speed and dead-letters
                              # work that was never bad. SQS is the opposite: the message is invisible for its
                              # visibility timeout either way, so sleeping here would only idle a worker that could
                              # be draining other messages.
                              if released_immediately:
                                  logger.info(
                                      "Backing off before the next attempt at an immediately-redelivered message",
                                      worker_id=worker_id,
                                         So on SQS the pool takes the same path it took on main: release,
                                         no sleep, next message. Both arms are covered by named tests —
