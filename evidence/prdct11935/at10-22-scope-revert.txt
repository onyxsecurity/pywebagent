  The ruling asks for proof, not assurance, so this section is a per-file walk of the whole diff with
  a measured basis for each verdict. Nothing here is "should be fine".

  4.2 Helm. Two kinds of change, both inert on AWS:
      * the gen-2 charts LOSE their scanner_events_asb / mcp_gateway_events_asb stanzas — every value in
        them was the empty string, so no AWS cell was configured through them;
      * endpoint-asset-ingestion GAINS asset_ingestion_asb + alert_processing_asb, both defaulting to "".
      The risk this creates is a cell whose flux-fleet values still carry a key the model no longer
      declares. common_core.config.BaseCustomSettings sets extra="allow" and Config inherits it, so such
      a key is accepted and ignored rather than rejected. Measured, by constructing each config WITH the
      removed stanza still present:

          mcp_gateway_consumer    cloud=aws    stale mcp_gateway_events_asb accepted+ignored, field gone: True
          endpoint_asset_ingestion cloud=aws   asset_ingestion_asb defaults empty -> ns='' queue=''; sqs url untouched=''
          all three default to cloud=aws and boot clean

  4.3 Dependencies. One line added to pyproject: azure-storage-blob>=12.27.1, in the base dependency
      group. It was already installed on every image as a transitive of the azure_mgmt extra; the change
      makes the direct import direct. Its only import site is common_core/services/blob_storage_client.py,
      which storage_factory imports lazily INSIDE the Azure branch, so an AWS pod's import graph is
      byte-identical. uv.lock is the lock of that one line.
