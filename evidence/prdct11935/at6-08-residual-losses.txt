  1. The fix IS an identity move. app_definition_id is {package_name}::{serial} on both sides, so
     changing what the writer puts in package_name moves bash::<serial> -> <script>::<serial>:

  2. The rule, quoted from the code that owns the identity
     (python_temporal_worker/mcp_asset_creation/activities.py:965-980):
               # Real callers that pass BOTH a URL and their own identity: Claude web connectors
               # ("Claude Connector: <name>" — the one that HAS been converged, below), remote MCPB
               # extensions ("mcpb:<bundleId>"), Bedrock AgentCore gateways (the gateway ARN) and Vertex
               # Agent Engine ids. Converging any of the others onto canonize_url(url) is a deliberate
               # identity MOVE, and an identity move is only safe together with the migration that
               # re-keys assets, app_definitions AND their access_control rows in the same change —
               # never deployed ahead of it.
               #

  3. The failure mode is a SECURITY failure, in the same comment:
               # what access_control.app_definition_id holds. Re-deriving the identity from the URL for
               # a caller that passes its own external identity therefore mints a NEW app_definition +
               # asset and leaves every existing rule pointing at an identity nothing reports any more —
               # the guard then finds no rule and returns the tenant default, silently turning an
               # enforced block into an allow on a default-allow tenant.
               #

  4. And it is a LOCKED PAIR. The repo's own CLAUDE.md requires any id-derivation change to be
     mirrored on the gateway/policy side IN THE SAME CHANGE. That mirror rebuilds the very key this
     fix would move, from the SHARED mcp_package_cache row (common/models/mcp_client_info.py:172):
               further appends ``::{container_id}`` to the device-scoped FILE form so
               each container's copy is a distinct asset. We mirror that here so
