## R-6 (added 2026-08-24, round 50) — the Azure alert-publish sender is shared and unserialised

Found while re-measuring onyx#12329's own ticket-reconciliation item 12 at its head `2b60fdc4df`.

**The hazard.** `endpoint_asset_ingestion` builds ONE `ASBQueueClient` alert-processing producer at boot
(`service.py:156-164`) and the sessions step sends one message per (session, policy) from concurrent
object-processing tasks. The Azure SDK's `ServiceBusSender` is not coroutine-safe, so two objects that both
carry sessions can race on the same AMQP link. The run measured exactly that before the fix existed: **1042**
`'NoneType' object has no attribute 'create_sender_link'` on the pre-fix pod, with the fan-out failing 100%
of the time (65 swallowed "failed to publish one session alert-processing request (continuing)").

**Why it is not fixed in that PR.** It was — and then owner ruling #2 (round 46) removed the queue-layer work
as superseded by `main` ("REMOVE FROM THIS PR ENTIRELY … the `abandon_message` method you added to `asb.py`
(KEEP `_system_properties`)"), and reducing `asb.py` to that single addition took the send serialisation with
it. At head `grep -rn '_send_lock' backend_python/src backend` → **0**, and `origin/main` carries no sender
lock either, so nothing upstream supersedes this half.

**Current exposure.** Not theoretical, but not currently firing: `kubectl logs deploy/eai-azure --since=24h`
shows **0** sender crashes and **0** publish failures on live lab traffic. Concurrency is 5 with
`max_messages=1`, so the race needs two session-carrying objects in flight together.

**Second half — the failure is unobservable on this lane.** The scanner lane meters only `published`
(`writers.py:648`) and `skipped_no_queue` (`:650`); `publish_failed` is emitted on the **gateway** lane alone
(`gateway_writers.py:420`). A scanner-lane producer failing every send moves no counter — the same
footgun-2 shape this ticket already tracks for R-4/R-5.

**What closing this needs:** serialise sends on the shared sender (or give each concurrent sender its own
client, the way the receive side already does), meter `publish_failed` on the scanner lane, and cover both
with a test that actually exists — the two tests onyx#12329's body used to cite
(`test_asb_sender_concurrency.py`, `test_session_alert_failure_is_metered.py`) are absent from `git ls-files`.
