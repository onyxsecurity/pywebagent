=== WHY THE EARLIER MEASUREMENT OF THIS AT WAS NON-ZERO — ROOT CAUSE, TO THE LINE ===
The round-40 re-drive of this AT reported a residual it could not attribute: the same MCP server
(same content hash 6ba6cf0f7d763862a90488822e1cb0df...) keyed `<abs>/dist/bundle.cjs::<serial>::unknown`
on the AWS-transport tenant and `node::<serial>::unknown` on the Azure-transport tenant, plus an
unpinned `mcp-remote` at 0.1.49 vs 0.1.46. It is NOT transport-caused. MCP identity derivation is
not a pure function of the payload bytes:

  1. backend_python/src/endpoint_asset_ingestion/ingestion/writers.py:916-926
     `await resolve_object_versions(...)` runs INLINE, before the first write, to "warm the package /

     of ::unknown".
  2. backend_python/src/endpoint_asset_ingestion/ingestion/version_resolution.py:378

     — a LIVE npm-registry "latest" HTTP GET at ingest time. The module docstring names it: "THE

  3. backend_python/src/endpoint_asset_ingestion/ingestion/mcp_writer.py:405-436
     identity name comes from `get_cache_entry_by_hash(...)` on the per-tenant `mcp_package_cache`

=== HARNESS DEFECTS FIXED FOR THIS MEASUREMENT (all harness, none in ~/onyx) ===
 D1  Writer-pod resolution state was never reset. Both prior harnesses truncated the tenants but
     reused long-running writer pods whose module-global mcp_package_cache LRU survives TRUNCATE.
     FIX: run-scoped writer clones (eai-at6-aws / eai-at6-azure), created cold, at the same instant,
     both on the head image — so neither side carries prior resolution state.
 D2  wipe-prefixes.sh is asymmetric by design: it empties the AWS object store in up to 6 passes and
     "by design" never empties the Azure one. FIX: this leg empties BOTH stores symmetrically at
     reset, and does not rely on wiping at all — it gates on both queues being empty instead.
 D3  The plan's parity sinks (s3_sink_parity_ta / azure_blob_parity_tb) are fed by
     `extract_tenant_id`, i.e. they copy EVERY consumer's traffic on the box into the two comparison
     tenants. With sibling legs scanning concurrently, the two tenants absorb different suffixes of
     the traffic stream. FIX: a run-scoped Kong consumer plus a dedicated `at11_route.at6r50` branch
     (the sanctioned round-48 at11 isolation pattern) so ONLY this leg's own POSTs can reach either
     tenant. Route condition also pins `x-source-type == "mcp-scanner"`, which excludes the
     scanner's separate `endpoint-logs` stream.
 D4  Object boundaries were left to chance. Two independently batching vector sinks can group a
     burst of POSTs into different object sets, and the writer's connection-source merge is
     arrival-order dependent. FIX: settle-gated SEQUENTIAL replay — body N+1 is not sent until N has
     landed as exactly one object in BOTH stores, BOTH queues are empty (SQS visible+in-flight = 0,
     Service Bus active = 0), and BOTH writers have logged their Nth `outcome=processed`.
 D5  Non-atomic dumps manufacture diffs. KEPT from the engineer's harness: both tenants are read
     inside ONE `REPEATABLE READ` transaction.
 D6  Gen-1 had to be quiesced, which perturbs shared state. NOT NEEDED HERE: this lane's objects
     live in a run-scoped bucket and a different storage account, so gen-1 (a scheduled lister over
     the shared `ingestion` bucket) is structurally unable to see them. Gen-1 ran untouched at
     replicas 1/1 throughout — a stronger isolation claim than quiescing it.
 Every wait in the harness is bounded (max iteration counts, `timeout`), and a leg that does not
 settle exits non-zero rather than dumping a partial state.
